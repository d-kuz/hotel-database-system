#  Система управления хостелом
Реляционная база данных для управления гостиничным фондом хостела, включающая оперативную базу данных (OLTP) для ежедневных операций и хранилище данных (DWH) для исторического анализа. Система автоматизирует процессы заселения, выселения, учёта платежей и дополнительных услуг.

# О проекте
Система разработана с учётом специфики хостелов, где в одном номере могут проживать несколько человек, но с строгими правилами: совместное проживание разрешено только для людей одного пола или для семей, занимающих номер целиком.


- Процедура заселения [check_in](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/sql/procedures/check-in) автоматически определяет «пол номера» при первом заселении, проверяет совместимость жильцов по полу, рассчитывает свободные места и обновляет статусы номеров (свободен/занят/мужской/женский).
- Функции проверки задолженности ([check_residents_pay](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/sql/functions/check_residents_pay), [check_services_pay](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/sql/functions/check_services_pay)): сравнивают начисленные суммы с оплаченными для проживания и дополнительных услуг, возвращая положительное значение при долге и отрицательное при переплате.
- Процедура выселения ([check_out_person](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/sql/procedures/check_out_person) c использует проверки задолженности с автоматическим переносом данных в хранилище данных: при успешном выселении данные из оперативных таблиц переносятся в хранилище для анализа
- Динамическое ценообразование: стоимость проживания рассчитывается на основе категории номера, количества ночей и занимаемых мест и дополнительных услуг; система автоматически суммирует стоимость при заселении семьи или группы.

# Архитектура системы

Система разделена на два логических уровня:

  [Оперативная БД](https://github.com/d-kuz/hotel-database-system/blob/d1c1bb7652538f62c952cc23ebf0930a3ad1c385/images/database.png):
  Оптимизирована для быстрых транзакций (заселение, выселение, оплата). Содержит нормализованные таблицы persons, rooms, categories, residents, pay_residents, pay_services.

  [Хранилище данных](https://github.com/d-kuz/hotel-database-system/blob/d5e3bc095e125e76f04d71534c025af3331c598c/images/storage.png):
  Оптимизировано для аналитических запросов. Использует схему «звезда» с таблицей фактов и измерениями. Данные переносятся сюда процедурой при выселении.
