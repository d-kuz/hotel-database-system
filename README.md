# 🏨 Система управления хостелом (Oracle Database)

Оперативная база данных и хранилище данных для гостиницы типа «хостел». 
Спроектирована и реализована реляционная база данных для управления 
гостиничным фондом.

## 🎯 О проекте

Система разработана с учётом специфики хостелов, где в одном номере 
могут проживать несколько человек, но с строгими правилами: совместное 
проживание разрешено только для людей одного пола или для семей, 
занимающих номер целиком.

### Ключевые возможности:
- **Умное заселение:** автоматическое определение «пола номера» при 
  заселении первого жильца и проверка совместимости при добавлении новых.
- **Динамическое ценообразование:** автоматический расчёт стоимости 
  проживания в зависимости от категории номера, вместимости и 
  количества ночей.
- **История клиентов:** при повторном заселении данные не заполняются 
  заново.
- **Учёт дополнительных услуг:** кабельное ТВ, доставка еды и др. с 
  интеграцией в итоговый счёт при выселении.
- **Автоматический перенос в DWH:** при выселении данные об оплате и 
  проживании архивируются в таблицы фактов хранилища данных для 
  последующей аналитики.

## 🏗️ Архитектура системы

Система разделена на два логических уровня:

1. **Оперативная БД (OLTP):** 
   Оптимизирована для быстрых транзакций (заселение, выселение, оплата). 
   Содержит нормализованные таблицы `persons`, `rooms`, `categories`, 
   `residents`, `pay_residents`, `pay_services`.

2. **Хранилище данных (DWH):** 
   Оптимизировано для аналитических запросов. Использует схему «звезда» 
   с таблицей фактов `h_fact_table` и измерениями. Данные переносятся 
   процедурой [`check_out_person`](sql/check_out_person.sql) при 
   выселении.

## 🧠 Ключевые бизнес-процессы (PL/SQL)

Система реализует строгие бизнес-правила на уровне базы данных с 
правильной декомпозицией логики. Каждый процесс состоит из главной 
процедуры и вспомогательных функций, которые выполняют конкретные 
проверки.

### 🚪 Процесс заселения

**Главная процедура:** [`check_in`](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/sql/procedures/check-in) — выполняет 
размещение гостя с проверкой условий. Поддерживает заселение одного 
гостя (с проверкой половой совместимости) и заселение семьи/группы 
(занимает номер целиком). Автоматически обновляет статус номера.

**Вспомогательные функции:**
- 🔢 [`free_places`](sql/free_places.sql) — рассчитывает количество 
  доступных мест в номере. [Пример кода →](#подсчёт-свободных-мест)
- ✅ [`check_status`](sql/check_status.sql) — проверяет половую 
  совместимость гостя с уже проживающими. 
  [Пример кода →](#проверка-совместимости-при-заселении)

---

### 📤 Процесс выселения

**Главная процедура:** [`check_out_person`](sql/procedures/check_out_person) — 
завершает проживание с автоматическим расчётом итоговой стоимости, 
проверкой задолженности и переносом исторических данных в хранилище 
данных для аналитики.

**Вспомогательные функции финансового контроля:**
- 💰 [`check_residents_pay`](sql/functions/check_residents_pay) — сверяет 
  начисленные и оплаченные суммы за проживание.
- 💰 [`check_services_pay`](sql/functions/check_services_pay) — сверяет 
  начисленные и оплаченные суммы за дополнительные услуги.

Обе функции блокируют процедуру выселения при наличии долга.

## 🛠️ Технологический стек

- **СУБД:** Oracle Database
- **Языки:** SQL, PL/SQL (функции, процедуры, триггеры)
- **Веб-интерфейс:** Oracle APEX
- **Методологии:** ER-моделирование, нормализация БД (до 3НФ), 
  проектирование хранилищ данных (DWH)

## 📂 Документация и схемы


- Процедура заселения [check_in]() автоматически определяет «пол номера» при первом заселении, проверяет совместимость жильцов по полу, рассчитывает свободные места и обновляет статусы номеров (свободен/занят/мужской/женский).
- Функции проверки задолженности ([check_residents_pay](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/), [check_services_pay](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/sql/functions/check_services_pay)): сравнивают начисленные суммы с оплаченными для проживания и дополнительных услуг, возвращая положительное значение при долге и отрицательное при переплате.
- Процедура выселения ([check_out_person](https://github.com/d-kuz/hotel-database-system/blob/2a49f224397a1662796ffab802501fbab25ec263/sql/procedures/check_out_person) c использует проверки задолженности с автоматическим переносом данных в хранилище данных: при успешном выселении данные из оперативных таблиц переносятся в хранилище для анализа
- Динамическое ценообразование: стоимость проживания рассчитывается на основе категории номера, количества ночей и занимаемых мест и дополнительных услуг; система автоматически суммирует стоимость при заселении семьи или группы.

# Архитектура системы

Система разделена на два логических уровня:

  [Оперативная БД](https://github.com/d-kuz/hotel-database-system/blob/d1c1bb7652538f62c952cc23ebf0930a3ad1c385/images/database.png):
  Оптимизирована для быстрых транзакций (заселение, выселение, оплата). Содержит нормализованные таблицы persons, rooms, categories, residents, pay_residents, pay_services.

  [Хранилище данных](https://github.com/d-kuz/hotel-database-system/blob/d5e3bc095e125e76f04d71534c025af3331c598c/images/storage.png):
  Оптимизировано для аналитических запросов. Использует схему «звезда» с таблицей фактов и измерениями. Данные переносятся сюда процедурой при выселении.
